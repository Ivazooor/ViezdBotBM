# Бот выездных фотоотчётов — настройка и запуск

Сотрудник создаёт отчёт прямо в Telegram, переписываясь с ботом: выбирает тип, проходит чек-лист,
выбирает существующий выезд или создаёт новый, вводит дату/ответственного/комментарий,
присылает фото и видео — бот собирает всё и пересылает в рабочий чат.

## Почему файлы до 2 ГБ работают без своего сервера

Сотрудник присылает видео **боту со своего телефона** — файл загружает его приложение Telegram (лимит
2 ГБ, с Premium 4 ГБ). Бот не скачивает и не загружает файл заново, а **пересылает его по `file_id`**
(`copyMessage`). Поэтому лимит бота в 50 МБ не действует, и не нужны ни `api_id`, ни свой Bot API сервер.

## Что нужно настроить

### 1. `TELEGRAM_BOT_TOKEN` — токен бота
@BotFather → `/revoke` (старый токен утекал в историю) → скопировать **новый** токен.

### 2. `TELEGRAM_CHAT_ID` — куда слать отчёты
1. Добавьте бота в рабочую группу (и дайте право писать).
2. Откройте в браузере: `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
3. Напишите любое сообщение в группе и обновите страницу — найдите `"chat":{"id":-100…}`.
   Для групп id **отрицательный** (например `-1003953057200`). Это и есть `TELEGRAM_CHAT_ID`.

### 3. `ALLOWED_USER_IDS` — кто может слать отчёты
Список Telegram ID сотрудников через запятую, например `12345678,98765432`.
- Узнать ID просто: пусть сотрудник напишет боту `/start` — бот ответит «Ваш Telegram ID: …».
- Добавьте эти ID в переменную и перезапустите сервис.

Бот также проверяет `BM_API_TOKEN` и при запуске спрашивает у CRM поддерживаемую версию API.
Без доступного CRM API версии 2 бот не начинает принимать отчёты и запросы на выдачу.
Действующий список допущенных сотрудников и оценщиков формируется из переменных окружения
и настроек в коде.

## Деплой на Timeweb Cloud (VPS, Ubuntu)

Бот работает по long polling — домен, SSL и webhook НЕ нужны, он сам подключается к Telegram.

1. Создать Cloud Server: Ubuntu 24.04, минимальный тариф (1 CPU / 1 ГБ). Запомнить IP и пароль root.
2. Подключиться к серверу (веб-консоль Timeweb в панели или `ssh root@<IP>`).
3. Установить Node.js и git:
   ```
   curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
   apt-get install -y nodejs git
   ```
4. Скачать код и зависимости:
   ```
   git clone https://github.com/Ivazooor/ViezdBotBM.git
   cd ViezdBotBM && npm install
   ```
5. Сначала выпустить на сайте CRM API с `GET op=capabilities`, возвращающим
   `visitReportsVersion: 2`, `reportJobsProtocol: claim-v1`, `attachReport: true`
   и `sourceChatId`, совпадающий с `TELEGRAM_CHAT_ID` бота.
   Затем создать файл `.env` (`nano .env`) и вписать (см. `.env.example`):
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `BM_API_TOKEN`, `ALLOWED_USER_IDS`.
   `BM_API_TOKEN` должен совпадать с токеном CRM API. При несовместимом API бот
   останавливается до начала Telegram polling.
6. Автозапуск через pm2 (рестарт при сбое и перезагрузке сервера):
   ```
   npm install -g pm2
   pm2 start backend/server.js --name viezdbot
   pm2 save && pm2 startup
   ```
7. Проверка: `pm2 logs viezdbot` → «Запуск Telegram-бота (long polling)». Затем боту `/start`.

### Дисковая очередь и переезд сервера

Бот хранит запросы на запись отчётов в CRM, захваченные задания выдачи и подтверждения доставки
в `data/report-outbox.json` относительно корня репозитория. Путь можно задать через
`REPORT_OUTBOX_PATH` в `.env`. Файл создаётся с правами `0600`, каталог — `0700` при создании;
пользователь процесса должен иметь права на запись в этот каталог. Файл игнорируется Git.

При обновлении кода оставляйте `data/report-outbox.json` на месте. При переезде сервера остановите
бота, скопируйте этот файл вместе с `.env` в соответствующий каталог нового сервера, проверьте
владельца и права `0600`, затем запускайте только один экземпляр бота. Не удаляйте файл и не
заменяйте его пустым: в нём могут быть ещё не записанные в CRM отчёты и неподтверждённые выдачи.
Повреждённый файл останавливает запуск и требует восстановления из резервной копии.
Если CRM вернула постоянный конфликт для отложенной записи отчёта, бот пишет `report_index`
в журнал (`pm2 logs viezdbot`) и откладывает повтор до пяти минут. Такой конфликт нужно
разобрать по ID отчёта в журнале и карточке CRM; удаление очереди не устраняет причину.
Если основная запись предварительного или заключительного отчёта не удалась, бот отдельно
сохраняет файлы для поиска через `attach_report`. Эта запасная операция не выставляет
отметки `checks.prelim`/`checks.final` и не обновляет тексты работ: руководителю нужно
проверить их в карточке по уведомлению бота.

> Если репозиторий приватный и `git clone` просит логин — проще временно сделать репозиторий
> публичным (в коде секретов нет, токен только в `.env`) или загрузить файлы на сервер вручную.

## Как пользуется сотрудник

1. Открывает бота в Telegram → `/start`.
2. Выбирает тип отчёта → читает чек-лист → «Продолжить».
3. Выбирает выезд из CRM либо создаёт новый, вводит дату, ответственного и сведения о работах.
4. Присылает все фото и видео (по одному или альбомом).
5. Жмёт «📤 Отправить отчёт» — всё уходит в рабочий чат и индексируется в карточке выезда.
   `/cancel` — отмена. Для просмотра из поиска мини-приложения бот копирует фото, видео и PDF
   в личный чат без скачивания крупных видео на сервер.
